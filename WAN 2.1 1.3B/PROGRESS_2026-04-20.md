# WAN 2.1 progress — 2026-04-20

## Что проверено

- APK до этой правки был фактически **SDXL-only** по UI и по основному run path.
- `phone_generate.py` уже знал про `--model-family wan21`, но умел только **runtime/readiness probe**, а не полноценный standalone prompt->video на телефоне.
- Текущая архитектура **не поддерживает true multi-resolution single `.bin.bin`**:
  - один context binary = одна фиксированная shape-конфигурация;
  - practical path = несколько fixed-shape contexts + общий runtime/server reuse.

## Что уже изменено в коде

### APK

- Добавлен toggle `WAN 2.1 basic debug` в главный экран.
- APK теперь умеет:
  - переключаться между обычным SDXL path и WAN basic-debug path;
  - автоматически подставлять `832x480` как sane default для WAN;
  - выбирать WAN base dir (`/data/local/tmp/wan21_t2v_qnn` / `/sdcard/Download/wan21_t2v_qnn`) без ручного ковыряния каждый раз;
  - отображать structured WAN summary вместо ожидания PNG.

### phone runtime

- `phone_generate.py` теперь для WAN:
  - автогенерирует `basic_debug` input raws из `*_qnn_manifest.json`, если готового `input_list.txt` нет;
  - не блокируется на отсутствии model `.so`, если уже есть готовый context binary;
  - выполняет честный probe в нескольких режимах:
    - direct `qnn-net-run`;
    - persistent server cold;
    - persistent server warm;
  - считает reuse gain / overhead;
  - печатает machine-readable `WAN_REPORT_JSON:` для APK.

### Deploy helper

- Добавлен `deploy_wan_basic_debug.py`:
  - раскладывает на телефон нужные QAIRT libs/bins;
  - пушит transformer Android `.so` и manifest;
  - может закинуть актуальный `phone_generate.py` в `phone_gen/generate.py`;
  - генерирует context binary прямо на устройстве.

- On-device `qnn-context-binary-generator` перезапущен с **правильным** `--binary_file` из manifest (`WanTransformer3D_wan_t2v_1p3b_832x480_17f_seq128_fp16.serialized.bin`), чтобы итоговый `.bin.bin` совпал с путём, который потом ожидает runtime check.
- Генератор context сейчас реально считает, а не висит мёртвым грузом: процесс `qnn-context-binary-generator` находится в состоянии `R`, а CPU counters в `/proc/<pid>/stat` растут между проверками.

- В этом runtime check пойман и исправлен реальный баг: manifest хранит `android_lib` как Windows path, а Android `os.path.basename()` не режет `\\`; добавлен `_portable_basename(...)`, после чего исчезло ложное `missing model/...`.
- После фикса собран и переустановлен новый APK; bundled runtime payload на телефоне обновлён до `apk-runtime-v0.4.3-wan-debug2`, внутри bundled `generate.py` присутствует `_portable_basename(...)`.

## Новый статус после thermal-fail

- Телефон после тяжёлой on-device генерации WAN context **реально перезагрузился**: `getprop ro.boot.bootreason -> reboot`, uptime после возврата в `adb` был около `300s`.
- После этой перезагрузки `qnn-context-binary-generator` уже не жив, а `/data/local/tmp/wan21_t2v_qnn/context/` остаётся пустым. То есть текущая попытка **не собрала context**, а оборвалась из-за thermal/reboot.
- Это подтверждает, что продолжать основную WAN context-сборку на самом телефоне в таком виде — плохая идея: устройство перегревается слишком сильно.
